# Task: wt-core (BitTorrent client core + all Webtor patches) — pure Rust port
Target: engine-rs/crates/wt-core/ only.
Change: Implement the public API already declared in engine-rs/crates/wt-core/src/lib.rs (keep signatures; you may add items; ask coordinator before breaking any) by porting the client/torrent/peer logic of engine-go/patches/torrent: client.go, torrent.go, peerconn.go, peer.go, requesting.go, request-strategy/, reader.go, piece.go, file.go, ratelimit, choking/unchoking + seeding, PEX handling, metadata exchange (ut_metadata) for magnets, piece hashing workers (PieceHashersPerTorrent), completion caching, half-open/established conn limits, dial rate limiting, peer high/low water, incoming connections, callbacks/status events, stats. Plus EVERY Webtor patch with identical semantics: webtor_urgent.go (SeekTuning, urgent stealing, request focus, faster focus peer, candidate budget, playback pipeline limit, refocus, nudge, playback interest, head-of-line rescue, hedging, slow peer yield, drop chokers, counters), webtor_arrival.go (learned block-arrival net, state save/load), hybrid magnet fix, outgoing TCP conn hook, CacheDialAddr, and the msg-writer wakeup fix (see WEBTOR_PATCH.md).
Uses: wt-meta (parsing, hashing), wt-wire (handshake, messages, MSE, uTP), wt-discovery (trackers, DHT, WebTorrent, web seeds), wt-types storage traits (storage is supplied by the engine). Those crates are being written in parallel: read their published APIs as they appear; ask the coordinator if something you need is missing; meanwhile build your state machine, picker and reader against internal traits so you are not blocked.
Design: one Tokio runtime owned by Client; per-connection reader/writer tasks; torrent state under a parking_lot Mutex held briefly (like the Go client lock) or an actor — your choice, but the blocking public API must not deadlock and Reader::read must block on a condvar/notify until verified data is available.
Constraints: performance at least Go's: request pipelining, no per-block heap churn, hashing off the network tasks, bounded queues. Do not implement storage (wt-storage) or engine policy (wt-engine/wt-policy).
Observable acceptance: port the library tests that matter (client_test.go transfers, reader tests, request-strategy tests, webtor_urgent_test.go, webtor_arrival tests, webtor_hybrid_test.go, issue regression tests where applicable) using an in-memory ClientStorage test double; a local 2-client TCP transfer of 64 MiB with verified data; a magnet (metadata via ut_metadata) transfer; a seek test: reader seeks into missing data and gets its first 64 KiB; throughput on loopback >= the Go library's on the same machine (measure Go with `go test` in engine-go/patches/torrent if needed and record both numbers in PORT_NOTES.md).
